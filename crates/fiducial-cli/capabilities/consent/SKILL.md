## When this capability is relevant

Install `consent` only when the product enables a provider with
`requires_consent = true` (currently: `meta-pixel-capi`) or declares
non-necessary cookie categories in `[legal] cookie_categories`. A product that
runs only cookieless analytics (`first-party`, `cloudflare-web-analytics`)
owes no banner, and shipping one would be incorrect.

## What installing this adds

- `pipelines/consent.toml` — `fid-consent` generates
  `apps/web/src/generated/consent.ts` from `[legal] cookie_categories`.
- `apps/web/src/components/cookie-consent.tsx` (web-next only) — the banner
  component imported by the layout.

## Configuration

No additional `fiducial.toml` block. The `consent` capability reads
`[legal] cookie_categories` and the analytics provider registry.

## Rules the banner is built to satisfy

- **Nothing non-necessary runs before a choice.** `consent.ts` exports
  `hasConsent(category)`, which returns `false` until a yes is recorded.
- **Refusing is as easy as accepting.** Both buttons have the same visual
  weight. A "reject all" that is a second click behind "settings" is the most
  commonly fined banner dark pattern in the EU.
- **No pre-ticked boxes.** Every optional category starts off.
- **Withdrawal is as easy as consent.** `openCookieSettings()` reopens the
  banner from a footer link.

## Adding the footer link

Call `openCookieSettings()` (exported from `cookie-consent.tsx`) from the
footer's "Cookie settings" link. The Cookie Policy page generated by
`fid-legal` promises this link exists.
