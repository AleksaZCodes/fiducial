# Skill: web-start

**Capability:** `web-start` · **Platform:** Fiducial {{version}}

---

## What this capability adds

A TanStack Start (React) app at `apps/web/`, server-rendered on a Cloudflare Worker.
Choose it when **end-to-end types matter**: typed routes and links, server
functions called like local functions, a lot of client state, and an app that does
not want the App Router's server-component model (the reason to pick it over
Next.js).

- **TanStack Router** file routes in `src/routes/`, with `src/routeTree.gen.ts`
  generated by `tsr generate` (and by `vite build`).
- **Server functions** (`createServerFn`): code that runs on the Worker, called from
  a loader or a component with its types intact and no API route written by hand.
- **`@cloudflare/vite-plugin`** on the `ssr` environment: `dev` and `build` run the
  server inside `workerd`, the runtime a deploy uses.
- **A server entry** `src/server.ts` wrapping Start's own handler to set the
  security headers from `src/security.generated.ts` on every response (derived by
  `fid derive` from the platform's one table; `[security] hsts_preload` is the only choice).
- **Tailwind 4 on the design tokens**: `src/styles.css` imports the `tokens.css` and
  `marks.css` the `design` capability installs into `src/app/`.

## Declare it

```toml
[apps.web]
framework = "tanstack-start"

[deploy]
shape = "tanstackstart"
```

`fid derive` writes `apps/web/wrangler.jsonc` with `main = "src/server.ts"` (the
Cloudflare Vite plugin adds the client assets itself). It names the product's own
entry on purpose: Start's package entry, `@tanstack/react-start/server-entry`,
builds its own handler and never reads `src/server.ts`, so a custom entry that is
only *in* `src/` sends none of its headers. Keep `nodejs_compat` in `compatibility_flags`: the `deploy`
capability seeds it, and Start needs it. `fid doctor` holds the framework and the
shape to agreeing, and fails an app whose `src/security.generated.ts` lacks a required header or has not
been derived yet.

## Build, run, deploy

```sh
pnpm install            # runs `wrangler types`, which needs the derived wrangler.jsonc
cd apps/web
pnpm dev                # vite dev, inside workerd, on :3000
pnpm typecheck          # wrangler types && tsr generate && tsc --noEmit
pnpm build
pnpm deploy             # vite build && wrangler deploy
```

## What this is not

- **Not static.** For a content site use `web-astro`.
- **No content editor, i18n routing, SEO or `content` accessors yet.** Those
  capabilities derive for Next.js and SvelteKit; their Start forms are not written.
- **No devtools.** The scaffold Cloudflare generates ships TanStack devtools; this
  template leaves them out so the production bundle carries none.
