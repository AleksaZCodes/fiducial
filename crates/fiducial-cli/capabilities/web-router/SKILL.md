# Skill: web-router

**Capability:** `web-router` · **Platform:** Fiducial {{version}}

---

## What this capability adds

A React Router 8 app (framework mode) at `apps/web/`, server-rendered on a
Cloudflare Worker. Choose it when the app is **routes and loaders more than
server components**: a dashboard, an internal tool, an app with a thin server. A
route's `loader` and `action` run on the Worker and reach the component typed, with
no hand-written API between them.

- **React Router 8**, `ssr: true`, with route types generated by `react-router typegen`.
- **`@cloudflare/vite-plugin`** on the `ssr` environment: `dev` and `build` run the
  server inside `workerd`, the runtime a deploy uses.
- **The Worker entry** `workers/app.ts` calls the request handler and sets the
  security headers from `app/security.ts` on every response.
- **Tailwind 4 on the design tokens**: `app/app.css` imports the `tokens.css` and
  `marks.css` the `design` capability installs into `src/app/`.

## Declare it

```toml
[apps.web]
framework = "react-router"

[deploy]
shape = "reactrouter"
```

`fid derive` writes `apps/web/wrangler.jsonc` (the name and `main = "workers/app.ts"`;
the Vite plugin adds the client assets itself, so they are not stated twice).
`fid doctor` holds the framework and the shape to agreeing, and fails an app whose
`app/security.ts` lacks a required security header.

## Build, run, deploy

```sh
pnpm install            # runs `wrangler types`, which needs the derived wrangler.jsonc
cd apps/web
pnpm dev                # react-router dev, inside workerd
pnpm typecheck          # wrangler types && react-router typegen && tsc -b
pnpm build
pnpm deploy             # react-router build && wrangler deploy
```

## Bindings

Add D1, R2, KV and the rest through `[adapters]` and `[deploy]` as for any Worker;
the derived `wrangler.jsonc` carries them. In a loader, read them from
`import { env } from "cloudflare:workers"`.

## What this is not

- **Not static.** The Cloudflare plugin supports neither SPA mode nor prerendering,
  so a content site belongs on `web-astro`.
- **No content editor, i18n routing, SEO or `content` accessors yet.** Those
  capabilities derive for Next.js and SvelteKit; their React Router forms are not
  written.
- **No `@fiducial/headless` components.** Add the ones a page needs.
