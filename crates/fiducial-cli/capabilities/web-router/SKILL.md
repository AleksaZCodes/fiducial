# Skill: web-router

**Capability:** `web-router` · **Platform:** Fiducial {{version}}

---

## What this capability adds

A React Router 8 app (framework mode) at `apps/web/`, **full stack** on a
Cloudflare Worker: the server and the UI are one app. Choose it when the app is
**routes and loaders more than server components**: a dashboard, an internal tool,
an app with a thin server.

The starter shows the whole loop, in `app/routes/home.tsx`:

| Piece | Where | What it does |
|---|---|---|
| **loader** | `home.tsx` | runs on the Worker for a GET; its result reaches the component typed |
| **action** | `home.tsx` | runs on the Worker for a POST; validates and answers with a `400` on bad input |
| **`<Form>`** | `home.tsx` | works with JavaScript off (a plain POST), and without a reload once hydrated |
| **server-only module** | `app/lib/greeting.server.ts` | the `.server` suffix keeps it out of the browser bundle |
| **resource route** | `app/routes/healthz.ts` | a loader with no component: a JSON endpoint, and the healthcheck the self-hosted target reads |

Everything a Worker has (D1, R2, KV, secrets) is reached from a loader or action
through `import { env } from "cloudflare:workers"`, typed by `wrangler types`, with
no hand-written API between the page and the data.

**React Router, not Remix.** React Router v8 (June 2026) is where the Remix v2
framework went: Remix v2 and React Router v6 are end of life. Remix 3 is a separate,
non-React project and is not what this installs.

- **React Router 8**, `ssr: true`, with route types generated by `react-router typegen`.
- **`@cloudflare/vite-plugin`** on the `ssr` environment: `dev` and `build` run the
  server inside `workerd`, the runtime a deploy uses.
- **The Worker entry** `workers/app.ts` calls the request handler and sets the
  security headers from `app/security.generated.ts` on every response (derived by
  `fid derive` from the platform's one table; `[security] hsts_preload` is the only choice).
- **Tailwind 4 on the design tokens**: `app/app.css` imports the `tokens.css` and
  `marks.css` the `design` capability installs into `src/app/`.

## Declare it

```toml
[apps.web]
framework = "react-router"

[deploy]
shape = "reactrouter"
```

`fid derive` writes `apps/web/wrangler.jsonc` (the name and `main = "workers/app.ts"`;
the Vite plugin adds the client assets itself, so they are not stated twice).
`fid doctor` holds the framework and the shape to agreeing, and fails an app whose
`app/security.generated.ts` lacks a required security header or has not been
derived yet (`fid derive` writes it).

## Build, run, deploy

```sh
pnpm install            # runs `wrangler types`, which needs the derived wrangler.jsonc
cd apps/web
pnpm dev                # react-router dev, inside workerd (Node 22.22+, React 19.2.7+)
pnpm typecheck          # wrangler types && react-router typegen && tsc -b
pnpm build
pnpm deploy             # react-router build && wrangler deploy
```

## Bindings

Add D1, R2, KV and the rest through `[adapters]` and `[deploy]` as for any Worker;
the derived `wrangler.jsonc` carries them. In a loader, read them from
`import { env } from "cloudflare:workers"`.

## What this is not

- **Not static.** The Cloudflare plugin supports neither SPA mode nor prerendering,
  so a content site belongs on `web-astro`.
- **No content editor, i18n routing, SEO or `content` accessors yet.** Those
  capabilities derive for Next.js and SvelteKit; their React Router forms are not
  written.
- **No `@fiducial/headless` components.** Add the ones a page needs.
