# fiducial:design — Claude Design Bridge

This product has the `design` capability. The component registry source
(`packages/ui-react/src/*.tsx`, `packages/ui-svelte`) is the **declaration**;
the Claude Design preview HTML with its `<!-- @dsCard … -->` marker is the
**derivation**, kept honest by `fid derive --check`.

## The insight

A preview HTML file is a *second representation* of a component this repository
already holds as source. Two representations of one thing is the relationship
this platform exists to manage — so the registry source is the declaration and
the Claude Design preview is a derivation, generated by a pipeline.

"Keeping the projects in sync" stops being a sync problem.

## The chain

```
[brand] → @fiducial/tokens CSS custom properties
                ↓
        packages/ui-react/src/*.tsx  (declaration)
        packages/ui-svelte           (declaration)
                ↓  fid derive        (pipeline: design — executor fid-design)
        components/<name>/index.html (derivation, @dsCard marker on line 1)
        _ds_manifest.json            (compiled index of all preview cards)
```

Adding Claude Design as a third consumer of `@fiducial/tokens` means brand
→ tokens → every registry → Claude Design is one chain. No fourth place
for design values to live.

## Session requirement

**This capability requires `/design-login` before any pipeline can run.**
`fid derive` will skip the `design` pipeline and print a reminder if the
`DesignSync` tool has not been authorized in the current session.

```
  ⚠ design pipeline skipped — run /design-login to authorize DesignSync
```

Once authorized, `fid derive` calls the `DesignSync` tool's
`list → finalize_plan → write` protocol — paths are locked and shown before
any write, one component at a time, never a wholesale replace.

## Preview HTML format

```html
<!-- @dsCard group="Components" name="Button" subtitle="Primary action" viewport="400x200" -->
<!DOCTYPE html>
<html>
  <head>
    <link rel="stylesheet" href="../../packages/tokens/dist/tokens.css">
  </head>
  <body>
    <!-- component preview -->
  </body>
</html>
```

The `<!-- @dsCard … -->` marker must be the **first line** of the file.
`_ds_manifest.json` is compiled from those markers by `fid derive`.

## Groups

Free-form, but the standard groups are: `Type`, `Colors`, `Spacing`,
`Components`, `Brand`.

## Validation

`.render-check.json` — `total / bad / thin / variantsIdentical` — is produced
by the pipeline and tracked in `fiducial.lock`. A component with `bad > 0` or
`thin > 0` fails `fid derive --check`.

## If DesignSync already handles this

The ROADMAP notes: if a `/design-sync` skill exists once `/design-login` has
run, **this capability is a thin adapter over it, not a pipeline to write**.
Verify before building any pipeline — building the pipeline anyway would be a
second implementation of a round trip that already works.
